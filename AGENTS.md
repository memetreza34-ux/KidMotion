# KidMotion Agent instructions — Phase 1 handoff

Applies to ALL future KidMotion episodes, including workout, pure learning and learn-and-move.

**MANDATORY after Phase 1 is finished:** Run the correct QA (`npm run prompt:qa -- --episode=<folder>` for workout / learn-and-move; `npm run learning:prompt:qa -- --episode=<folder>` for pure learning) or `npm run phase1:links -- --episode=<folder>`. The two verified source files are `00-bildprompts/google-flow-prompt.txt` and `01-voice-script/voice-script.txt`. QA automatically writes `PHASE1_START_HIER.md` and `99-technik/PHASE1_HANDOFF.json` and prints two links. Commit/push the completed files and handoff before promising working tablet links. **Then always add two separately clickable links to the CHAT ANSWER** (not only a code block, document or console):

- [Google-Flow-Prompt öffnen](https://github.com/memetreza34-ux/KidMotion/blob/main/episodes/<episode-folder>/00-bildprompts/google-flow-prompt.txt)
- [Voice-over-Skript öffnen](https://github.com/memetreza34-ux/KidMotion/blob/main/episodes/<episode-folder>/01-voice-script/voice-script.txt)

Replace `<episode-folder>` with the actual episode folder. Link directly to the two content files, not to repository root or a placeholder. Mobile use: view/copy prompt into https://flow.google.com and voice text into TTS; a GitHub link does not automatically fill Google Flow. If QA fails, explain the blocker and do not claim Phase 1 is finished or link to an unpushed draft as completed. This is an ongoing requirement, not a one-off for KM-008. Do not generate images simply because Phase 1 is complete; cover selection and existing permission gates still apply.

## Flow missing picture recovery (every new workout)
Google Flow may return no image. After each scene, confirm a real downloadable PNG; save immediately with `npm run flow:save -- --episode=<folder> --scene=N --source=<real-file>`. Then run `npm run flow:verify -- --episode=<folder>`; inspect `99-technik/FLOW_RETRY_MISSING.json`. Retry ONLY files without a saved valid PNG using their original prompts; never replace an existing scene or move numbers to fill gaps. `npm run flow:batch` gives `RECOVER_MISSING_FIRST` if earlier scenes are missing. At the end run `npm run phase2:finalize -- --episode=<folder>`, repeat for missing files, and demand 28 real images before Phase 3. Agent interacting with Flow must perform the generation: the CLI only checks existing files. After 3 repeated technical failures, stop and clearly report the blocker, never invent an image.

## TOP PRIORITY: Continue improving after EVERY actual finished video

Read `quality/README.md`, `config/continuous-improvement.json` and recent `quality/reviews/*.json` before planning. This is the most important quality rule for every new Playvilo/KidMotion production. First run `npm run quality:gate`. Any unfinished real-video review blocks further new-episode creation. The renderer creates `quality/reviews/<episode>.json` as **PENDING** after successful output; then a reviewer must watch the actual whole MP4, take timestamped notes and record concrete script, Flow art, animation, visual, timing, TTS, sound, captions, teaching/safety and export problems. Never auto-mark a review PASS or pretend that a prompt review equals watching a video.

Every new episode (workout, learning and learn-and-move) contains `99-technik/IMPROVEMENT_BRIEF.md` and `99-technik/IMPROVEMENT_APPLICATION.json`. Phase-1 QA blocks release until each applicable active lesson in the improvement policy is marked APPLIED with an exact meaningful **quotation in its prescribed actual prompt/plan file** and a specific explanation of the fix. Quotes are source-checked. A policy change requires `npm run quality:brief -- --episode=<folder>`. Observe actual next-video quality and viewer retention in YouTube Studio when metrics are available, then evolve rules with concrete tests and verified observations. Never fabricate engagement metrics or claim guaranteed perfect videos. New motions or production engine changes require a coordinated safety-tested revision.

## Mandatory uncluttered 03-export layout for every future episode

Do not recreate separate title, description, caption or timing files in `03-export`. The only public `.txt` file is `YOUTUBE_UPLOAD.txt` (one full title plus one description with EXACTLY FIVE distinct hashtags). Approved `FINAL_VIDEO.mp4` and `COVER.png` remain the other two outputs. All `UPLOAD_METADATA.md`, `SUBTITLES.srt`, `VOICE_TIMESTAMPS.txt` and `VIDEO_TIMELINE.txt` live in `99-technik`, for optional use, but not in 03-export. This applies equally to workout, learning, and learn-and-move, without changing the required two Phase 1 chat links.

Phase-1 QA and postrender QA must validate this special-case. Google Flow: no written HELLO in source PNG; Remotion draws a large HELLO! badge visible from video frame 0.
